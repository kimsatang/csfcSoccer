# CSFC 팀짜기 — 팀 편성 알고리즘 (자동 균형)

> 2026-11-04부터 기본 방식은 팀장 드래프트(`05-시즌-드래프트.md`). 이 알고리즘은 코드·테스트로 유지하며, 드래프트 없이 임시로 팀을 짜야 할 때 다시 화면에 붙일 수 있다.

구현: `src/features/build-teams/buildTeams.ts` · 테스트: `buildTeams.test.ts`

## 1. 입력과 출력

- **입력**: 참석자 목록, 팀장 id 3개, 부주장 id 3개
- **출력**: 3개 팀 (각 팀 = 팀장 1 + 부주장 1 + 팀원 N), 비용(cost, 낮을수록 균형)

## 2. 제약 (반드시 지킴)

1. 팀장·부주장은 각 팀에 정확히 1명씩
2. 모든 참석자는 정확히 한 팀에 배치
3. 팀 간 인원 차 ≤ 1

## 3. 균형 비용 함수

```
cost = 10  × (팀 평균 실력 최대 − 최소)
     +  1  × (팀 실력 합 최대 − 최소)        ※ 팀 인원이 모두 같을 때만
     + 1.5 × Σ(DF·MF·FW 각각 팀별 인원 최대 − 최소)
     +  4  × (주포지션 GK 인원 최대 − 최소)
     +  6  × (GK 가능자가 0명인 팀 수)   ※ 전체 GK 가능자 ≥ 3명일 때만
```

가중치는 `WEIGHTS` 상수로 분리되어 있어 운영 피드백에 따라 조정한다. 실력 균형이 가장 중요하고, 그다음 GK, 포지션 순이다.

균형도 표시 기준: cost < 3 아주 균형 · < 6 균형 · < 10 보통 · 그 이상 불균형

## 4. 절차

```
1) 리더 페어링
   팀장을 실력 내림차순, 부주장을 실력 오름차순 정렬 후 짝지음
   → 가장 강한 팀장 + 가장 약한 부주장

2) 무작위 재시작 40회 반복
   a. 리더 페어를 무작위로 팀(빨강/파랑/노랑)에 배정
   b. 탐욕 배치: GK 먼저, 이후 (실력 + 작은 난수) 내림차순으로 한 명씩
      - 인원이 가장 적은 팀들 중에서
      - (팀 실력 합 + 같은 포지션 인원×2 − GK 없는 팀이면 50) 이 가장 작은 팀에 배치
   c. 지역 탐색(hill climbing): 개선이 없을 때까지 반복
      - 두 팀 간 팀원 1:1 맞교환 → cost 감소 시 채택
      - 인원 많은 팀 → 적은 팀으로 1명 이동 (인원 차 ≤1 유지) → cost 감소 시 채택

3) 다양성 선택
   40개 결과 중 최저 cost + 0.6 이내 후보들 가운데 무작위 1개 선택
   → '다시 섞기'를 눌러도 균형은 유지하면서 매번 다른 조합
```

팀장·부주장은 1단계에서 고정되며 2-c의 교환·이동 대상에서 제외된다.

## 5. 복잡도

참석 n명, 팀원 m = n−6. 지역 탐색 1패스는 팀 쌍 3개 × (m/3)² 교환 ≈ m²/3회 평가. 실측: 24명 약 20ms, 40명 약 120ms (목표: 40명 1초 이내 ✅).

## 6. 검증 (vitest)

| 테스트 | 기준 |
|---|---|
| 팀장·부주장 배치 | 각 팀 1명씩 |
| 전원 배치 | 누락·중복 없음 |
| 인원 균형 | 24/23/22/10/7명 모두 차이 ≤1 |
| 실력 균형 | 샘플 24명, 시드 20개 모두 평균 차 ≤0.5 |
| GK | GK 가능자 ≥3이면 모든 팀에 1명 이상 |
| 다양성 | 시드 8개 중 2개 이상 다른 조합 |
| 검증 | 팀장/부주장 수 오류, 중복 지정 시 에러 |

## 7. 알려진 한계와 개선 아이디어

- **종합 실력 하나로만 균형** — 공격형 7점과 수비형 7점을 같게 본다. → 세부 능력치 도입 시 비용 함수에 항 추가.
- **리더 페어링 고정** — 운영진이 짝을 직접 정하고 싶을 수 있다. → 페어 수동 지정 옵션.
- **관계 조건 없음** — 같은 팀 금지/필수 미지원. → 비용 함수에 큰 패널티 항으로 추가하면 구조 변경 없이 지원 가능.
- **팀 수 고정(3)** — `TEAM_COUNT` 상수와 색상 배열만 바꾸면 확장 가능하도록 작성.
