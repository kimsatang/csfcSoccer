# CSFC 팀짜기 — 개발·배포 가이드

## 1. 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | React 19 + TypeScript | 팀 표준 |
| 빌드 | Vite 8 | 빠른 개발 서버, 정적 빌드 |
| 상태 | `useReducer` (+ 당일 초안은 localStorage) | 화면 상태는 단순하게 유지 |
| 백엔드 | Supabase (Postgres + Auth + RLS) | 회원·경기 기록 저장, 운영진 매직링크 로그인 |
| 테스트 | Vitest | 드래프트 순서·경기일·편성 알고리즘 단위 테스트 |
| 배포 | Vercel (정적) | 무료 플랜, GitHub 연동 자동 배포, 프리뷰 URL |
| UI | Mantine 9 + Tabler Icons, Pretendard | 모바일 우선 컴포넌트(바텀시트·모달·알림·하단 탭바), 전술판만 커스텀 CSS |

## 3. 로컬 실행

```bash
npm install
cp .env.example .env.local   # Supabase URL / publishable key
npm run dev      # http://localhost:5173
npm test         # 알고리즘 테스트
npm run build    # dist/ 생성 (tsc 타입체크 포함)
npm run preview  # 빌드 결과 확인
```

Node 20 이상 권장.

## 4. Vercel 배포

### 최초 1회
1. 저장소: `kimsatang/csfcSoccer`
2. vercel.com → **Add New → Project** → 저장소 Import
3. Framework Preset이 **Vite**로 자동 인식되는지 확인 (Build `npm run build`, Output `dist`)
4. **Environment Variables**에 `.env.example`의 두 값 등록 (`VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`)
5. **Deploy** → 발급된 URL을 Supabase Auth의 Site URL/Redirect URLs에 등록 (5-4)

`vercel.json`에 SPA rewrite가 들어 있어 이후 라우터를 추가해도 새로고침 404가 나지 않는다.

### 이후
- `main` 브랜치 push → 프로덕션 자동 배포
- PR 생성 → 프리뷰 URL 자동 생성 (운영진에게 미리 보여주기 좋음)

### CLI로 배포할 경우
```bash
npm i -g vercel
vercel        # 프리뷰
vercel --prod # 프로덕션
```

| 테이블 | 내용 |

### 5-2. 접근 정책 (RLS)
- `anon`(비로그인)은 모든 테이블 권한 없음 (예외: `invite_info` RPC — 토큰을 아는 경우 초대 정보만)
- 역할별 상세 권한표는 `06-팀장-초대-팀관리.md` 1절
- 슈퍼 관리자(`admins.role = 'SUPER'`): 전체 + 운영진 관리, 회원 삭제, 드래프트 재오픈·확정 팀 수정, 모든 팀 라인업
- 운영진(`admins`): 회원 관리(삭제 제외), 드래프트 진행, 경기 당일, 팀 관리 조회
- 팀장·부팀장(`team_leaders`): 회원(실력·메모 제외)·시즌·드래프트 조회, 자기 팀 차례 지명, 자기 팀 참석·라인업 관리
- 그 외 로그인 사용자: 0건 조회, 쓰기 거부
- 판별 함수 `private.is_admin()`은 API에 노출되지 않는 `private` 스키마에 둠

### 5-3. 운영진 추가/삭제
- **슈퍼 관리자: 김동인(`ehddls128@gmail.com`)** — 앱 **회원 → 운영진 관리**에서 운영진 추가·삭제 (RLS: 슈퍼 관리자만 가능, 슈퍼 관리자 행은 삭제 불가)
- 대시보드에서 직접 할 때는 Table Editor → `admins`에 이메일(소문자) 행 추가. 또는 SQL Editor:
```sql
insert into public.admins (email, name) values ('someone@example.com', '홍길동');
delete from public.admins where email = 'someone@example.com';
```

### 5-4. Auth URL 설정 (대시보드에서 1회)
Authentication → URL Configuration (초대 링크는 `/?invite=토큰`으로 돌아오므로 `/**` 패턴 필수)
- **Site URL**: Vercel 프로덕션 URL (예: `https://csfc-soccer.vercel.app`)
- **Redirect URLs**: `http://localhost:5173/**`, `https://*-<vercel팀>.vercel.app/**`(프리뷰용), 프로덕션 URL

설정하지 않으면 매직링크가 localhost:3000으로 열린다.

### 5-5. 이메일 발송 한도
Supabase 기본 메일 서버는 시간당 발송 수가 매우 적다(테스트용). 운영진이 많아지면 Authentication → SMTP Settings에 외부 SMTP(Resend 등)를 연결한다.

### 5-6. 저장 범위
- **DB**: 회원, 시즌·팀·드래프트 지명, 저장한 경기 기록
- **기기 localStorage**: 경기일별 참석 체크·오늘만 이동 (경기 기록 저장 전까지)

### 5-7. MCP로 마이그레이션할 때 주의
`delete`·`drop`이 들어간 SQL은 Supabase 쪽 확인 단계가 필요해 자동 실행이 취소된다. 삭제가 필요한 작업(예: 지명 되돌리기)은 RLS가 허용하는 범위에서 앱이 직접 행을 지운다.
