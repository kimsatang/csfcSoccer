## 2. 앱 구성

```
apps/web     → sportclub.axhelper.co.kr        (구단 운영 서비스, PWA)
apps/admin   → admin-sportclub.axhelper.co.kr  (백오피스, 직원 전용)
packages/shared  → 타입, 도메인 로직(편성·드래프트·이름 인식), UI 공통
supabase/    → 마이그레이션, Edge Functions
```

- 모노레포(pnpm workspace). 지금 코드는 `apps/web`으로 옮기고, 순수 로직(`buildTeams`, `draft`, `parseNames`, 포메이션)은 `packages/shared`로 분리
- Vercel 프로젝트 2개(같은 저장소), Supabase 운영·개발 2개
- 백오피스는 DB 관리자 권한을 브라우저에 두지 않음 → Edge Function에서 직원 권한 확인 후 처리

## 3. 권한

| 구분 | 역할 | 범위 |
|---|---|---|
| 직원(백오피스) | 슈퍼 / CS | 전체 구단·계정·이슈 / CS는 조회·답변·한도 조정 |
| 구단 | 오너 | 구단 설정, 운영진 임명, 인계, 삭제 |
| | 운영진 | 회원, 일정·경기, 참석, 편성, 대회 |
| | 팀장 | 맡은 팀(대회 고정팀·경기 팀)의 지명·라인업 |
| | 회원 | 본인 참석 응답, 명단·라인업 조회 |

- 팀장은 구단 역할이 아니라 **대회 팀 / 경기 팀에 붙는 역할** (회원도 지정 가능, 계정이 없으면 초대 링크)
- 권한은 RLS의 `private.club_role(club_id)`, `private.leads_team(...)`로 판단 (지금의 is_admin·is_super·leads_team 일반화)

## 4. 데이터 모델 초안

**계정·구단**
- `profiles` — 사용자 표시 이름, 연락처(선택)
- `clubs` — slug(주소), 이름, 엠블럼, 색, 주경기장·주소·좌표, 지역, 기본 종목, 소개, 단톡방 링크, `status`(베타는 active), `plan`(beta), `limits`(jsonb: 회원 수 등), 삭제 예정일
- `club_members` — 구단 × 계정 × 역할(owner/admin/member)
- `club_invites` — 토큰, 역할, 연결할 선수, 만료, 사용 기록 (지금의 team_invites 일반화)
- `ownership_transfers` — 인계 요청·수락·거절 기록
- `beta_codes` — 초대 코드, 사용 한도·횟수, 만료 / `app_settings` — 가입 방식 등

**선수**
- `players` — 구단별 명부 (이름, 년생, 포지션, 등번호, 실력, 메모, 참석률, 상태, 연결 계정)
- `player_aliases` — 카톡 닉네임 등 별칭 (구단 내 고유)

**경기 운영**
- `schedule_rules` — 이름, 요일, 시간, 종목, 인제, 구장 → "다음 n주 경기 만들기" 요청 시 경기 생성
- `matches` — 날짜·시간·구장, 종목, 인원(인제 ± 조정), 유형(자체전/상대전), 팀 수, 상대 이름, `opponent_club_id`(비워 둠), 대회 id(선택), 투표 마감·정원, 상태
- `match_rsvps` — 경기 × 선수 × 응답(참/불/미정), 출처(링크/가져오기/운영진), 대기 순번, 시각
- `match_teams` / `match_team_members` — 그날 팀과 소속 (대회 고정팀이면 대회 팀에서 복사, 용병은 이름만)
- `games` / `lineups` — 1경기·2경기…, 대진, 점수(선택), 팀별 포메이션·자리
- `attendance_imports` — 가져오기 기록 (출처, 투표 인원, 인식 인원, 실행자)

**대회 (지금 이벤트 기능 일반화)**
- `competitions` — 이름, 기간, 종목, 상태 / `competition_teams` — 팀, 색, 팀장·부팀장 / `draft_picks` / `team_leaders`

**서비스 운영**
- `support_tickets` / `ticket_messages` — 분류, 내용, 첨부, 자동 정보(구단·화면·버전·기기), 상태
- `notices` — 배너 공지, 대상(전체/구단), 노출 기간
- `staff_users` — 직원 역할
- `audit_logs` — 누가(사용자/직원) 어느 구단에서 무엇을 바꿨는지 (권한·인계·삭제·한도 변경 필수)

**유료화 대비로 미리 두는 것:** `clubs.status`·`plan`·`limits`, 상태별 쓰기 제한을 RLS 함수 하나(`private.club_writable`)로 모아 두기

## 5. 주요 흐름

1. **가입:** 카카오 로그인 → (초대 코드 모드면 코드 입력) → 구단 목록
2. **구단 선택·생성:** 구단 카드 목록, 마지막 구단 기억, 상단 전환 메뉴 / 생성 → 오너가 됨
3. **구성원:** 운영진 초대 링크, 선수 명부 등록(CSV·붙여넣기), 선수에 계정 연결 초대
4. **인계:** 오너가 대상 지정 → 대상 수락 → 역할 교체 + 감사 로그
5. **경기:** 정기 규칙에서 "다음 n주 만들기" 또는 단건 생성 → 투표 링크 공유(카톡 공유) → 응답·가져오기로 참석 확정(인원 검증) → `자동 배정` 버튼 또는 수동·드래프트 → 라인업(종목별 전술판) → 이미지 공유 → (선택) 점수
6. **대회:** 고정팀 + 팀장 드래프트 + 기간 내 경기들이 대회 팀을 그대로 사용 (지금 11월 이벤트 방식)

## 6. 백오피스 (베타)

- **구단:** 목록·검색, 상세(회원 수·경기 수·최근 활동), 한도 조정, 오너 강제 이전(요청·본인 확인 후), 삭제 복구(30일 내)
- **계정:** 검색, 소속 구단, 정지, 탈퇴 처리
- **이슈:** 티켓 목록·배정·답변·상태
- **공지:** 배너 작성·대상·기간
- **설정:** 가입 방식(공개/초대 코드), 초대 코드 발급
- **감사 로그:** 조회·필터
- 직원 로그인은 별도 허용 목록 + 2단계 인증

## 8. 로그인·식별 정책 (닉네임·프로필만)

- 카카오 동의 항목: `profile_nickname`, `profile_image`만. `account_email`은 비즈 앱 전용이라 받지 않음
- Supabase 카카오 설정에서 **Allow users without an email** 켜기
- 모든 권한·초대·운영진 판별은 **이메일이 아니라 계정 id(user_id) 기준**으로 설계 (지금 프로토타입의 `admins.email`, `team_invites.preassigned_email` 방식은 쓰지 않음)
- 이메일이 없으므로: 공지·CS 답변은 앱 안에서, 계정 찾기는 카카오 재로그인으로, 오너 강제 이전 시 본인 확인은 구단 운영진 확인 + 카카오 계정 정보로
- CSFC 이전 시 기존 이메일 계정은 카카오 계정을 연결(identity linking)하거나 초대 링크로 다시 연결
- 투표 링크 응답(로그인 없음)의 오남용 방지: 링크 토큰 + 이름 선택 + 기기 기억, 운영진이 응답 수정 가능

## 11. 경쟁 서비스 참고 (PitchMaster)

- 조기축구·풋살 팀 관리, 카카오 가입, 현재 전면 무료(추후 월 9,900원 수준 구독 예고, AI 호출 비용 회수 목적)
- 넓은 기능: 참석 투표·리마인더·정원, AI 라인업·쿼터 로테이션, 경기 기록·MVP·시즌 시상, 회비 OCR, 회칙·벌금·게시판
- **라커룸의 차별점**: 카톡 투표를 그대로 가져오기(회원이 앱을 안 깔아도 됨) + 인원 검증, 자체전 특화(2~4팀·팀장 드래프트·대회 고정팀), 팀장 단위 권한·실력 비공개, AI 호출 없는 낮은 운영비
- 베타 후보(선택 대기): 데모 구단, 대리 투표·미응답자 독려, 선착순 정원·대기 승격, 용병 모집 링크, 공정 출전 로테이션, 풋살 키퍼 룰렛, 구장 지도·날씨, 회장 0명 방지, 골·어시·MVP 기록
