# CSFC 팀짜기 — 선수 데이터 모델

## 1. 설계 원칙

1. **입력 부담 최소화** — 운영진이 회원 한 명당 10초 안에 입력할 수 있어야 한다. 그래서 필수는 3개(이름·주포지션·실력)뿐이다.
2. **편성에 실제로 쓰는 값만 필수** — 알고리즘이 쓰지 않는 값은 선택 또는 이후 단계로 미룬다.
3. **회원 정보(마스터)와 경기 당일 정보(참석·역할)를 분리** — 팀장/부주장은 매 경기 바뀌므로 회원 속성이 아니다.
4. **개인정보는 받지 않는다** — 연락처·생년월일은 팀 편성에 필요 없으므로 프로토타입에서 제외.

## 2. 회원(Player) — 프로토타입 필드

| 필드 | 타입 | 필수 | 설명 | 편성에 쓰는 방식 |
|---|---|---|---|---|
| `id` | string | ✅ (자동) | 내부 식별자 | — |
| `name` | string | ✅ | 이름 (동명이인은 `홍길동A`처럼 구분) | 표시 |
| `mainPosition` | `GK` \| `DF` \| `MF` \| `FW` | ✅ | 주 포지션 | 포지션 분포 균형, GK 배치 |
| `skill` | 1~10 정수 | ✅ | 종합 실력 | 팀 평균·합계 균형 (가장 큰 가중치) |
| `subPosition` | Position | 선택 | 부 포지션 | GK 가능자 판단 (부포지션 GK도 키퍼로 인정) |
| `backNumber` | number | 선택 | 등번호 | 표시 |
| `status` | `ACTIVE` \| `INACTIVE` | ✅ (기본 ACTIVE) | 활동/휴면 | 휴면은 참석 목록에서 제외 |
| `memo` | string | 선택 | 운영진 메모 (예: "무릎 부상 회복 중", "주말만") | 표시 |

### 포지션을 4개로만 나눈 이유
동호회 경기에서 CB/LB/RB, CM/DM/AM을 구분해 균형을 맞추면 입력만 번거롭고 효과는 작다. 4분류로 시작하고 필요하면 세분화한다. CSV에서는 `CB`, `ST`, `수비수`, `공격` 같은 표현도 자동으로 4분류로 변환된다.

### 실력(skill) 1~10 기준표 (권장)

| 점수 | 기준 |
|---|---|
| 9~10 | 선수 출신급, 혼자 경기 흐름을 바꿈 |
| 7~8 | 동호회 상위권, 공수 모두 안정적 |
| 5~6 | 평균, 자기 포지션 역할 수행 |
| 3~4 | 경험이 적거나 체력 부족 |
| 1~2 | 입문자 |

> 운영진 2~3명이 각자 매긴 뒤 평균을 쓰면 편향이 줄어든다. 점수는 민감할 수 있으므로 공유 텍스트에서는 기본 숨김을 권장한다.

## 3. 경기 당일 상태(Match Session)

| 필드 | 타입 | 설명 |
|---|---|---|
| `attendance` | string[] | 참석자 id 목록 |
| `roles` | `Record<id, 'MEMBER'\|'CAPTAIN'\|'VICE'>` | 당일 역할 |
| `matchTitle` | string | 공유 텍스트 제목 |
| `teams` | Team[] \| null | 편성 결과 |

```ts
interface Team {
  index: number      // 0=빨강, 1=파랑, 2=노랑
  captain: Player
  vice: Player
  members: Player[]  // 팀장·부주장 제외
}
```

## 4. 이후 단계 후보 필드

| 필드 | 목적 | 도입 조건 |
|---|---|---|
| `attack` / `defense` / `stamina` (1~5) | 종합 실력만으로는 공격수 몰림 등을 못 잡을 때 세부 균형 | 종합 실력 편성 결과에 불만이 반복될 때 |
| `preferredFoot` (L/R/Both) | 측면 배치 참고 | 포메이션 기능 도입 시 |
| `ageGroup` (20대/30대/40대+) | 체력 균형 | 연령대 편차가 큰 경우 |
| `joinedAt` | 신입 회원 분산 배치 | 신입이 몰리는 문제 발생 시 |
| `attendanceRate` | 출석률 통계 | 서버 저장 + 경기 이력 도입 후 자동 계산 |
| `avoidWith` / `pairWith` (id[]) | 같은 팀 금지/필수 (가족, 친구, 갈등) | 운영진 요청 시 |
| 경기 결과(승/무/패, 득점) | 실력 점수 자동 보정 (Elo 등) | 서버 저장 + 결과 입력 기능 도입 후 |

## 5. CSV 형식

```csv
이름,등번호,주포지션,부포지션,실력,상태,메모
홍길동,7,FW,MF,8,활동,
김철수,1,GK,,6,활동,주말만 가능
```

- 필수 컬럼: `이름`, `주포지션`, `실력` (헤더 이름 기준, 순서 무관)
- 엑셀에서 표를 복사해 붙여넣으면 탭 구분으로 자동 인식
- 포지션 별칭: `GK/골키퍼/키퍼`, `DF/수비/CB/LB/RB`, `MF/미드/CM/DM/AM`, `FW/공격/ST/CF/LW/RW`
- 상태: `휴면`/`inactive`이면 휴면, 그 외는 활동

## 6. 서버 저장 전환 시 테이블 (안)

```sql
create table members (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  back_number int,
  main_position text not null check (main_position in ('GK','DF','MF','FW')),
  sub_position text check (sub_position in ('GK','DF','MF','FW')),
  skill smallint not null check (skill between 1 and 10),
  status text not null default 'ACTIVE',
  memo text,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

create table matches (
  id uuid primary key default gen_random_uuid(),
  title text not null,
  played_on date not null,
  created_at timestamptz default now()
);

create table match_players (
  match_id uuid references matches(id) on delete cascade,
  member_id uuid references members(id),
  role text not null default 'MEMBER',  -- MEMBER | CAPTAIN | VICE
  team_index smallint,                   -- 0,1,2 (편성 확정 시)
  primary key (match_id, member_id)
);
```
